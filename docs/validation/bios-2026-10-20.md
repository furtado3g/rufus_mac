# Legacy BIOS boot validation — 2026-10-20

**Result: PASS** for `--mode extract` on QEMU/SeaBIOS x86_64 with both MBR and
GPT layouts. Fedora 44 reached the Anaconda installer from both images, and
Alpine 3.24.2 reached a login prompt with `boot/grub/grub.cfg`. The same Fedora
MBR image reached Anaconda under QEMU/OVMF, and the GPT image reached the GRUB
menu under OVMF, so legacy BIOS support did not regress UEFI boot.

This run uses the bundled GRUB 2.14 i386-pc assets and the integrated installer
(no manual GRUB commands after extraction).

## Extraction

```console
$ target/debug/image2usb write /tmp/isos/fedora.iso \
    --output /tmp/m4-fedora-mbr.img --yes --mode extract --verify
$ target/debug/image2usb write /tmp/isos/fedora.iso \
    --output /tmp/m4-fedora-gpt.img --yes --mode extract --scheme gpt --verify
```

Both runs reported:

```text
[finalizing]  installing GRUB BIOS bootloader for boot/grub2/grub.cfg
Extracted 321 files (8 directories, 1.1 GiB)
```

The MBR extraction took 16.7 s and the GPT extraction 16.2 s, including
read-back verification of every extracted file. The source ISO is not hybrid,
so extraction mode was required.

| Check | MBR image | GPT image |
| --- | --- | --- |
| Bytes 0–2 | `eb 63 90` (GRUB `boot.img`) | `eb 63 90` |
| Kernel sector at 0x5C | 34 | 34 |
| Boot drive at 0x64 | `0xFF` | `0xFF` |
| Partition entry | type `0x0C`, active `0x80` | protective type `0xEE`, inactive |
| Core at LBA 34 | magic `52 56` | magic `52 56` |
| Diskboot blocklist at 0x1F4 | start 35, count 283, segment 0x820 | start 35, count 283, segment 0x820 |
| Partition table | MBR preserved | primary GPT header `EFI PART` at LBA 1, first usable LBA 34, partition at 1 MiB |

The core length is 284 sectors; its first sector is loaded by `boot.img` and the
blocklist loads the remaining 283 sectors from LBA 35. The FAT32 partition starts
at 1 MiB, so neither the core nor its blocklist overlaps the filesystem.

## Fallbacks and limits

- Images without `boot/grub/grub.cfg` or `boot/grub2/grub.cfg` (for example Arch)
  are extracted with UEFI boot only and print a warning. Use DD mode if BIOS
  boot is required.
- 4Kn targets (4096-byte logical sectors) skip the BIOS installer and keep UEFI
  boot; the legacy chain assumes 512-byte sectors.
- syslinux-based images and Windows BOOTMGR are not implemented.
- Physical legacy BIOS hardware has not been tested. No physical USB device was
  written during this validation.
